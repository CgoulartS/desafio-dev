## Story

**As a** usuario do sistema,
**I want** cadastrar, listar, editar e excluir clientes,
**so that** eu possa gerenciar os passageiros que farao reservas.

## Acceptance Criteria

1. Model `Cliente` com campos: nome (CharField), email (EmailField), cpf (CharField com max_length=11), telefone (CharField)
2. ListView em `/clientes/` exibindo tabela com nome, email, CPF, telefone e acoes
3. CreateView em `/clientes/novo/`
4. UpdateView em `/clientes/<id>/editar/`
5. DeleteView em `/clientes/<id>/excluir/` com confirmacao
6. Validacao: email unico, CPF unico (unique=True)
7. Mensagens flash de sucesso para todas as operacoes
8. Todas as views protegidas por `LoginRequiredMixin`
9. Testes unitarios e de integracao (min. 5 testes)

## Complexity Estimate

**Size:** S (Small)
**Points:** 3
**Justificativa:** CRUD padrao seguindo o pattern da Story 1.3. Unica diferenca: unique constraints em email e CPF com validacao customizada.

## Risks

- **IntegrityError em unique constraints:** Se a validacao no form falhar, o banco lanca IntegrityError. Mitigacao: validacao dupla — no form (clean) e no model (unique=True).
- **CPF sem validacao de digito verificador:** Apenas valida 11 digitos numericos, nao calcula digito verificador. Mitigacao: aceitavel para escopo do desafio (nao e requisito).

### Validacao de CPF

```python
class ClienteForm(forms.ModelForm):
    class Meta:
        model = Cliente
        fields = ['nome', 'email', 'cpf', 'telefone']

    def clean_cpf(self):
        cpf = self.cleaned_data.get('cpf')
        if not cpf.isdigit() or len(cpf) != 11:
            raise forms.ValidationError('CPF deve conter exatamente 11 digitos numericos.')
        return cpf
```

### Unique Constraints no Model

```python
class Cliente(models.Model):
    nome = models.CharField(max_length=200)
    email = models.EmailField(unique=True)
    cpf = models.CharField(max_length=11, unique=True)
    telefone = models.CharField(max_length=20)
```
