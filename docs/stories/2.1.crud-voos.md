## Story

**As a** usuario do sistema,
**I want** cadastrar, listar, visualizar detalhes, editar e excluir voos,
**so that** eu possa gerenciar os voos disponiveis para reserva.

## Acceptance Criteria

1. Model `Voo` com campos: aviao (ForeignKey para Aviao), origem (CharField), destino (CharField), data (DateField), horario (TimeField)
2. ListView em `/voos/` exibindo tabela com aviao, origem, destino, data, horario e acoes
3. DetailView em `/voos/<id>/` mostrando detalhes do voo e lista de reservas/passageiros
4. CreateView em `/voos/novo/` com select de avioes existentes
5. UpdateView em `/voos/<id>/editar/`
6. DeleteView em `/voos/<id>/excluir/` com confirmacao
7. Validacao: aviao deve existir (integridade referencial)
8. Mensagens flash de sucesso para todas as operacoes
9. Todas as views protegidas por `LoginRequiredMixin`
10. Testes unitarios e de integracao (min. 5 testes)

## Complexity Estimate

**Size:** M (Medium)
**Points:** 5
**Justificativa:** CRUD similar ao de Avioes + DetailView adicional. ForeignKey para Aviao requer widgets de data/hora customizados.

## Risks

- **Widgets de data/hora:** Input type="date" e type="time" podem ter comportamento diferente entre navegadores. Mitigacao: Bootstrap 5 normaliza a maioria dos casos.
- **DetailView com reservas vazias:** Template voo_detail.html referencia reservas que so existirao na Story 2.3. Mitigacao: usar condicional `{% if object.reservas.all %}` para exibir tabela.
- **CASCADE no delete de Aviao:** Excluir um aviao remove todos os voos vinculados. Mitigacao: pagina de confirmacao deve alertar sobre isso.

### Widgets de Data/Hora

```python
class VooForm(forms.ModelForm):
    class Meta:
        model = Voo
        fields = ['aviao', 'origem', 'destino', 'data', 'horario']
        widgets = {
            'data': forms.DateInput(attrs={'type': 'date'}),
            'horario': forms.TimeInput(attrs={'type': 'time'}),
        }
```
